# Скелет подхода: как собирать курс по любому предмету

Выведен из курса «Английский A0→B1». Подходит для DevOps, математики, программирования, любого навыка, где есть теория и практика.
Английский здесь — только пример наполнения.

---

## 1. Принципы (на чём всё держится)

1. **Понимание до заучивания.** Сначала «что это и зачем» простыми словами, потом формулы и таблицы.
2. **Порядок обязателен.** Тема открывается, только когда освоена предыдущая.
3. **Темы переплетаются.** Старое постоянно возвращается в новых заданиях — это и есть повторение.
4. **Обратная связь сразу.** После каждого ответа — «почему так», а не только «верно / неверно».
5. **Сложность растёт за счёт качества заданий, а не их количества.**
6. **Точность.** У задания ровно один верный ответ, всё фактически и грамматически выверено.

---

## 2. Структура курса

```
Курс
 └─ Уровни (A1 → A2 → B1  /  Junior → Middle  /  База → Продвинутый)
     └─ Модули — одна тема на модуль, порядок жёсткий
         └─ каждый 8-й модуль — Обзор
```

- Уровень = 20–30 тем. Тема опирается только на уже пройденные.
- Два вида модулей:
  - **грамматические / концептуальные** — правило, механизм (Present Perfect · права в Linux · производная);
  - **тематические** — словарь и ситуации (еда, дом, здания города · сети, логи · задачи на проценты).
  Чередовать: тема-лексика даёт контекст, тема-правило — инструмент.
- Источник порядка — один файл (`order.js`), логика порядка — `ROADMAP.md`.

---

## 3. Шаблон модуля (всегда одинаковый)

| Блок | Что внутри | Объём |
|---|---|---|
| **Что это и зачем** | Что за явление простыми словами; как это «по-нашему» (по-русски / руками без инструмента); когда используют; главная идея одной фразой | 3–6 предложений |
| **Правило / суть** | Формула, таблица, схема, примеры с переводом / результатом | сколько нужно, без воды |
| **Как запомнить / Как тренировать** | Приём запоминания или упражнение. Заголовок — по смыслу, а не всегда «Как запомнить» | 1–3 предложения |
| **Ловушки** | Формат строго: **✗ ошибка → ✓ правильно → почему** | 2–5 пунктов |
| **Практика** | 22–28 заданий разных типов, у каждого пояснение | см. раздел 4 |

Правило подачи: **не распыляться, но и не обрывать.** Формула без объяснения «что это» — непонятно; лекция на три экрана — не читают.

---

## 4. Типы заданий

| Тип | Цвет | Английский | DevOps | Математика |
|---|---|---|---|---|
| Выбор | синий | правильная форма | правильная команда | верный ответ |
| Впиши | жёлтый | слово, форма | команда, флаг, путь | число, формула |
| Собери | фиолетовый | предложение из слов | шаги пайплайна | шаги решения |
| Чтение | бирюзовый | текст + вопросы | лог, конфиг, вывод команды | условие задачи |
| На слух | розовый | аудио + вопрос | — (или голосовая инструкция) | — |
| Исправь ошибку | (внутри «впиши») | неверная фраза | сломанный конфиг | неверное решение |

Группы внутри модуля: **Базовые** (правило в чистом виде) · **Учебник** (формат экзаменов / сертификаций) · **Разговор / Практика** (живые ситуации) · **Смешанные** (с прошлыми темами).
Каждое задание закрывает навык: понимать (чтение, на слух), строить (собери, впиши), применять (смешанные, ситуации).

---

## 5. Переплетение тем (фазы)

| Фаза | Где | Что в модуле |
|---|---|---|
| — | первый уровень и первые **30%** второго | только своя тема |
| лёгкое | **30–50%** второго уровня | 4–6 заданий опираются на прошлые темы, формат простой |
| усложнено | после **50%** второго уровня | 7–9 смешанных: две темы в одном задании, исправь ошибку, чтение |
| всё вперемешку | последний уровень | около половины заданий смешанные, формат реальной работы / экзамена |

- Смешанное задание помечено ↺ и ссылкой на тему, на которую опирается. Ссылки — **только назад**.
- Количество заданий **не растёт**. Старые задания **заменяются** смешанными (с корректным сбросом прогресса по заменённым).
- Пороги в тексте называть точно («с модуля 36»), а не «с трети».

---

## 6. Обзоры

- **Каждый 8-й модуль.** Накопительные: обзор 1 = темы 1–7, обзор 2 = 1–14, … обзор N = все пройденные.
- Половина заданий — по свежим 7 темам, половина — по всему раньше.
- **На 20% сложнее:** без подсказок, меньше времени в режиме скорости, две-три темы в задании, длиннее тексты, обязательно чтение и «на слух / разбор».
- Те же 24–28 заданий, что и в обычном модуле.

---

## 7. Прохождение и прогресс

- Следующий модуль открывается при **60%** верных в текущем (одна константа, меняется в одном месте).
- Правило можно читать всегда, закрыта только практика.
- Кнопка **«Открыть без прохождения»** — для повторения и смены устройства (прогресс в браузере не переносится).
- Режим «на скорость»: выбор за ограниченное время — проверка автоматизма.
- Прогресс модуля виден в боковой панели, обзоры выделены цветом, закрытые — замком.

---

## 8. Подача

- **Цвет = тип задания** (см. раздел 4), смешанные — отдельный оттенок.
- **Раскраска частей** в примерах: кто / помощник / действие / объект / где / когда (для кода: команда / флаг / аргумент / путь).
- После ответа: верно / неверно → правильный ответ → **пояснение** → полная фраза с подсвеченным ответом → (ссылка «Повтори тему ↺»).
- Мобильная версия обязательна: без горизонтальной прокрутки, модули сворачиваются.
- Для языков: транскрипция (эталон), ударения подсвечены везде, озвучка — как помощь, не эталон.

---

## 9. Чек-лист качества (перед публикацией)

**Задание**
- [ ] ровно один верный вариант; остальные варианты **не являются тоже верными**
- [ ] есть пояснение «почему»
- [ ] ссылки ↺ только на пройденные темы
- [ ] опирается только на то, что уже объяснено (нет тем «из будущего» без пометки)
- [ ] единый вариант нормы (британский английский / одна версия инструмента)

**Модуль**
- [ ] есть «Что это и зачем»
- [ ] ловушки в формате «ошибка → правильно → почему», правильное не зачёркнуто
- [ ] 22–28 заданий, есть все типы, есть чтение
- [ ] фаза смешивания соблюдена

**Курс**
- [ ] обзоры на каждом 8-м месте
- [ ] автоматическая проверка (`npm run check`) без ошибок
- [ ] проверено в браузере, в том числе на ширине телефона

---

## 10. Технический каркас и навигация

- Исходники разбиты по файлам: **модуль = файл**, словарь-тема = файл, движок отдельно.
- Сборка в **один HTML** (`npm run build`), минификация, проверка данных (`npm run check`), карта курса (`npm run map`).
- `README.md` в корне — таблица «задача → какие файлы открыть»; `README.md` в каждой папке; `ROADMAP.md` — порядок, фазы, статус.
- Цель навигации: чтобы для любой правки (своей или ИИ) нужно было открыть **один файл и соседние**, а не весь курс.
- Замены и дополнения — через маленькие помощники в конце файла модуля: `SWAP` (заменить задание), `EXPL` (пояснение), `INTRO` (вводный блок).
- Git: каждый блок работы — отдельный коммит; публикация после каждого блока.

## 11. Что ты указывал (требования, собранные за работу над курсом)

**Состав**
- Темы по британским учебникам (English File и др.): go/have/get, предлоги места и движения, Past Simple, исчисляемые/неисчисляемые, quantifiers, сравнительная/превосходная, going to (планы и прогнозы), наречия, verb + to, артикль the, Present Perfect и сравнение времён; B1 — по британским учебникам.
- Тематические модули: еда и напитки, правильное/неправильное питание (белки, жиры, углеводы…), дом и его «внутрянка», мебель, гарнитуры, действия, verb phrases, рутина, здания и их назначение (больницы, школы, БЦ, ТЦ).
- Если модуля по теме нет — добавлять.
- Дополнить словарь, раскрасить задания.

**Логика**
- После первого уровня и ~30% второго — лёгкое переплетение («предподготовка», модуль должно быть реально пройти).
- После 50% — усложнять. Количество вопросов не увеличивать — только сложность, вариативность, темы.
- Переплетение обязательное: слова, чтение, письмо, понимание, грамматика, построение предложений.
- Каждые 8 модулей — модуль со всем пройденным, на 20% сложнее.

**Качество**
- 99.9999% чёткости и грамматической верности.
- Ловушки и советы должны быть понятны — с объяснением, а не просто «так нельзя».
- Тема должна быть объяснена: не распыляться, но чтобы было понятно, что это вообще такое.
- Ударения — везде.

**Удобство**
- Работает на телефоне.
- Прогресс теряется при смене устройства → возможность открыть модуль без прохождения.
- Формулировки точные («с модуля 36», а не «с трети»).

**Процесс и техника**
- README по блокам и навигация (роадмап), чтобы не держать весь контекст.
- Сборка, скрипты в `package.json`, малый вес.
- Всё — в git.

---

## 12. Как начать новый курс по этой схеме

1. **Цель и уровни.** Кто учится, с какого уровня, к какому результату (например, DevOps: «с нуля до junior»).
2. **Список тем** по уровням (20–30 на уровень), чередовать концептуальные и тематические; источник — признанные программы (учебники, сертификации).
3. **ROADMAP:** порядок, номера, где обзоры (каждый 8-й), где границы фаз (30% / 50% второго уровня).
4. **Типы заданий под предмет** (раздел 4): что значит «впиши», «собери», «чтение» в этой области.
5. **Пилот:** 3 модуля + 1 обзор → проверить, понятно ли, и поправить шаблон.
6. **Остальные модули** по шаблону, блоками с публикацией.
7. **Переплетение** в модулях после 30% второго уровня, затем обзоры.
8. **Чек-лист качества** (раздел 9) + автоматическая проверка + проверка в браузере и на телефоне.
