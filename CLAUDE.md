## Первые команды в новой сессии
```bash
npm run status   # что готово, следующий модуль, что осталось, последние коммиты
npm run check    # сборка + проверка данных (должно быть «ошибок нет»)
```

## Цикл работы над модулем (делать именно так)
1. `npm run status` → следующий id.
2. `npm run new -- <id>` → заготовка `src/modules/L<N>/<id>.js`.
3. Заполнить через **Write** (не через bash heredoc — см. «Подводные камни»).
4. `npm run check` → 0 ошибок, 22–28 заданий.
5. Отметить ✅ в `ROADMAP.md` (для уровня 1 — колонка статуса).
6. `git add -A && git commit -m "Модуль N: тема" && git push`.
7. Опубликовать `artifact.html` через Artifact tool (тот же file_path).
8. Коротко отчитаться пользователю: что внутри, что дальше.

## Обязательное в каждом модуле (check.js проверяет)
- `case` — «Ситуация»: живая история + `<p class="goal"><b>Цель модуля:</b> …</p>`. Отвечает «зачем это вообще» ДО теории.
- `intro` (что это и зачем, какую боль решает), `theory`, `memo`, `traps` [ошибка, правильно, почему].
- `ex` 22–28, у каждого `e` — полноценное «почему», а не одно слово. Варианты без дублей, ровно один верный.
- `lab` — руками без ИИ; у каждой хотя бы `h` (подсказка) или `chk` (как проверить себя), лучше и `sol`.
- `qa` (вопросы собеса), `cheat` (в общую шпаргалку).
- Ссылка на другой модуль — **только** `модуль [[mod:id]]` (номер подставит движок). Номера не хардкодить.
- HTML-теги в тексте — только из белого списка; `<pid>` писать как `&lt;pid&gt;`.
- Каждые 8 модулей — обзор (`REV`), на 20% сложнее, реальный вывод команд, `ref` на прошлые модули.

## Правила пользователя (важно)
- **Коммиты без упоминаний Claude** (никаких Co-Authored-By). Пушить после каждого модуля.
- **Сначала «зачем», потом «как»**: не «как в школе». Каждая тема — ситуация и цель; каждый инструмент, упомянутый раньше своего модуля, — в `terms.js`.
- **Курс первичен, проект подстраивается под модули** (не наоборот).
- **CI**: GitLab CI и GitHub Actions — полностью и в паре; Jenkins — только главное.
- **Реальные кейсы** пользователя (из его Notion) — пересказывать через наш проект «Магазин» и наши лабы; не переносить названия компаний, IP, хосты, секреты. Курс открыт по ссылке.
- База проекта — **MS SQL Server** (Oracle — легаси-тикет 1.5). Полигон — WSL2 на ноутбуке (16 ГБ, x86-64); VPS по желанию (Спринт 0, тикет 0.10).
- Работать **маленькими шагами**: читать только нужные куски файлов, не выгружать большие файлы в контекст (вкладка VS Code падает от переполнения).
- Можно и нужно высказывать своё мнение и предлагать улучшения.

## Подводные камни среды (Windows + Git Bash)
- **Bash heredoc и sed съедают обратные слэши** (`\s`, `\\`, `\n`). Файлы с кодом писать через Write; правки — node-скриптом, записанным через Write, с абсолютным путём проекта: `node script.js "$(pwd -W)"`.
- В шаблонных строках модулей: `\\` → `\`; литеральный `${…}` писать как `\${…}` или `${'$'}{…}`.
- `sed` с `/` или `|` в тексте ломается — использовать Edit или node.
- Публикация артефакта: после первой публикации в новой сессии площадка может потребовать прочитать живую версию — читать с `path`, а не целиком (файл ~400 КБ).
- Проверка в браузере: skill `browser-automation` (`browser.mjs`, `--eval`, `--script`, скриншоты).
